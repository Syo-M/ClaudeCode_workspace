# トークン節約の運用ガイド

> Pro プランの上限に当たりにくくするための運用指針。CLAUDE.md からは自動参照されません。困った時に Read します。

## 基本戦略: エスカレート式

「最初から強いモデルを使う」のではなく、**必要な時だけエスカレートする**。

```
Haiku(設計・調査)  →  Sonnet(実装)  →  Opus(難所のみ)
```

| フェーズ | モデル | 目的 |
|---|---|---|
| 計画 / 探索 / 規約レビュー | **Haiku** | 安価で十分。広範囲の読み込み向け |
| 実装 / リファクタ / テスト | **Sonnet** | コスト効率の主力 |
| 設計議論 / 難バグ / 大規模変更 | **Opus** | 本当に必要な時だけ |

切替は `/model` コマンド、または起動時 `claude --model <id>` で。

## 二段階フロー: Plan → Execute

1. **Plan Mode**(`Shift+Tab` で切替)で実装計画だけ立てる。コード生成しない
2. プランを承認したら通常モードに戻り、実装に入る

メリット:
- 設計の往復が安いモデル(Haiku)で済む
- ボツプランで Opus トークンを溶かさない
- 計画が明文化されるので後で再開しやすい

## セッションを長く引きずらない

**1 つの長いチャット < 3 つの細分化されたチャット**

理由: 過去のやりとり全てが毎ターンのコンテキストに乗る。無関係な履歴が積もるほど 1 ターンの単価が上がる。

**目安:**
- タスクが終わったら `/clear` または新セッション
- 30 分以上同じセッションで作業していたら見直す
- 別の機能・別の関心事に移る時は必ず新セッション

ただし、**継続のメリットが大きい時**(同じファイルを連続編集中、長いデバッグ中)は維持。判断は「次のターンで前の文脈を再説明する必要があるか?」で。

## プロジェクト分離

`projects/<name>/` 配下で作業すると、無関係なプロジェクトのファイルが grep / find に巻き込まれない。

- 起動時に `cd projects/<name>` してから `claude` を立ち上げる
- ルートで起動するのは複数プロジェクトを横断する時だけ

## サブエージェントへの委譲

広範囲の探索・読み込みは Explore サブエージェントへ。
親のコンテキストには要約だけ返るので、長い grep 結果や大量のファイル内容が積もらない。

`/explore <query>` を使うか、明示的に `Agent(subagent_type=Explore, ...)` を呼ぶ。

## 出力を絞る

- `git log` は `--oneline -20` のように件数を絞る
- `find` の結果は `head` を通す
- 大きなファイルは `Read` の `offset` / `limit` で部分読み

## チェックリスト

トークン上限が近い時、まず以下を確認:

- [ ] セッションが 30 分以上続いていないか?(続いていたら `/clear`)
- [ ] Opus を使う必然性があるか?(なければ Sonnet に降格)
- [ ] 全文 Read している大きなファイルがないか?
- [ ] 同じ調査を Explore 経由でやれば短くならないか?
